# Подготовка GitHub и релиза

Рекомендуемое имя, описания на русском и английском, темы и тег находятся в `repository.json`. Готовые короткие и расширенные описания — в [ABOUT.md](../ABOUT.md). Это метаданные для заполнения GitHub, а не выполняемая настройка аккаунта.

## Перед публикацией

Откройте [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md): для полного комплекта пока не установлены условия исходного Telegram-бота. Найдите разрешение/лицензию или замените этот компонент до публичного распространения. Не выбирайте автоматически Apache/MIT для всего репозитория.

Проверьте `python tools/check_public.py`, тесты и состав коммита. Исходный архив не содержит историю старого рабочего репозитория, внутренние отчёты, настройки роутера и бинарники. Не загружайте родительскую рабочую папку целиком.

## Репозиторий

Создайте пустой репозиторий с выбранным именем. В каталоге публичных исходников:

```sh
git init -b main
git add .
git diff --cached --stat
git commit -m "Prepare Pivas custom31 sources and documentation"
```

Далее используйте SSH/HTTPS URL, который покажет GitHub, для `git remote add origin ...` и `git push -u origin main`. Команды push здесь не выполняются автоматически. Включите приватные сообщения об уязвимостях в Security и защиту основной ветки по необходимости.

## Release

1. Соберите пакеты по [DEVELOPMENT.md](DEVELOPMENT.md).
2. Создайте тег `v1.1.9-25-custom31` на проверенном коммите.
3. Подготовьте **draft / pre-release** с названием и текстом из [RELEASE_NOTES.md](../RELEASE_NOTES.md) и [RELEASE_NOTES.en.md](../RELEASE_NOTES.en.md). Можно разместить обе версии в одном описании Release.
4. Прикрепите все файлы из `release-assets/`: архивы обеих архитектур и common, IPK полного комплекта для отправки в Telegram, манифест и SHA256SUMS. Исходники доступны по тегу GitHub.
5. Проверьте скачивание, контрольные суммы и установку на тестовом роутере. Затем отдельно публикуйте релиз.

Готовые install-pivas-full.sh лежат внутри архивов архитектур: у файлов одинаковые имена, поэтому выкладывать оба под одним именем в Release нельзя. Зависимости Entware по-прежнему скачиваются при установке.

Выпуск нельзя считать аппаратно проверенным на всех моделях только потому, что CI зелёный. В описании пишите конкретно выполненные проверки.
