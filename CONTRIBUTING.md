# Участие в разработке

Опишите проблему, ожидаемый результат и способ воспроизведения. Для сетевых ошибок укажите модель, архитектуру Entware, версию KeeneticOS, Pivas и транспорт слота. Используйте тестовые адреса и ссылки без настоящих учётных данных.

Не добавляйте в коммиты `dist`, бинарники vendor, конфигурации живого роутера, резервные копии, логи и локальные пути. Для изменений DNS/маршрутов добавьте проверку в существующие тесты с имитацией роутера. Инструкция запуска — [DEVELOPMENT.md](docs/DEVELOPMENT.md).

PR должен описывать проблему, изменённое поведение и выполненные проверки. Отдельно отметьте миграции конфигов и необходимость перезапуска служб. Не объявляйте аппаратную проверку пройденной, если тестировали только имитацию.

Сохраняйте авторство и условия стороннего кода. Не добавляйте чужие исходники без установленной лицензии. Условия собственных новых файлов — Apache-2.0, если явно не указано иное и это совместимо с изменяемым компонентом.
