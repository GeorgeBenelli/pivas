# Разработка и сборка

## Модульные тесты

Нужны Python 3.11+ и системные `sh`, `tar`, `openssl`. Для импортов бота нужна библиотека requests. Тесты используют временные каталоги и имитацию роутера; root и подключение к Keenetic не нужны.

```sh
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements-dev.txt
python tools/check_public.py
python -m unittest discover -s tests -q
```

## Веб на компьютере

```sh
python tests/preview_web.py 8879
```

Откройте `http://127.0.0.1:8879`. Это демо с вымышленными настройками, авторизация в нём отключена. Оно привязано только к loopback; не публикуйте его в сеть. Никакой реальный роутер не меняется.

Для браузерных тестов в другом терминале (Node.js 22):

```sh
npm ci
npx playwright install chromium
npm run test:web
```

Можно передать `PLAYWRIGHT_MODULE` и `CHROMIUM_PATH`, если Playwright/Chromium установлены нестандартно. Пути конкретного компьютера не зашиты. Скриншоты создаются в `docs/ui-*.png` и не коммитятся автоматически.

## Получение бинарников

Для полной сборки нужен Go **1.26.6**. `GO_BINARY` позволяет указать путь к нему. Компилятор проверяется скриптом сборки Xray MIPSel. Исходники сторонних проектов загружаются из закреплённых URL и проверяются SHA-256.

```sh
python tools/fetch_xray.py
python tools/build_quic_probe.py
python build.py
python tests/verify_dist.py
python tools/package_release.py
```

`fetch_xray.py` загружает официальный Xray 26.3.27 для AArch64 и пересобирает MIPSel из закреплённых исходников с Go 1.26.6. Обычный официальный MIPS-бинарник, собранный другим Go, не подменяет совместимую сборку. QUIC-помощник собирается для обеих архитектур, его зависимости закреплены в go.mod/go.sum.

Каталоги кэша по умолчанию находятся во временной директории ОС. Для Go можно передать `GOCACHE`, `GOMODCACHE`, `GOPATH`. Бинарники vendor игнорируются Git; лицензии и манифесты сохраняются. При пересборке проверяйте изменения манифестов, а не объявляйте бинарники идентичными только по версии.

`build.py` запускает тесты и создаёт 17 IPK/установщиков плюс manifest.json в `dist/`. Старое содержимое **dist удаляется**, поэтому не храните там резервные копии. `verify_dist.py` проверяет совпадение исходников с пакетами и вложенными установщиками. `package_release.py` группирует их по архитектурам и добавляет документацию/лицензии; готовые файлы лежат в `release-assets/`.

## Структура

| Путь | Содержимое |
| --- | --- |
| `work/orig/data` | Исходники ядра Pivas и шаблоны файлов `/opt` (историческое имя каталога) |
| `work/orig/control` | Метаданные и скрипты установки ядра |
| `web-src` | Веб-сервер, HTML/CSS/JS и пакет |
| `bot` | Бот и встроенная telebot |
| `xray-src` | Init-обёртка Xray |
| `tools/quic-probe` | Исходники одноразового QUIC-помощника |
| `vendor` | Лицензии, происхождение и локально получаемые бинарники |
| `tests` | Модульные, браузерные и дополнительные сетевые тесты |

Дополнительные `*_e2e.py` для транспортов требуют специально подготовленных исполняемых файлов и локальных серверов; они не заменяются unit-тестами. Аппаратные проверки — холодный запуск, смена WAN, DNS, маршруты и исключения — выполняются отдельно на поддерживаемом Keenetic.

GitHub CI запускает unit и веб-тесты. Отдельный workflow сборки запускается вручную, выгружает файлы как artifact и не создаёт публичный Release.
